## 무엇을
우리 파이프라인(LoMa + MAGSAC++ + 호모그래피, 8방향 탐색)을 외부 데이터셋 UAV-VisLoc 03번 시퀀스에 학습 없이 적용했습니다. 위성 블록은 GPS 중심이고, 정답 위치는 블록 중심(x_norm = y_norm = 0)입니다. 바꾼 것은 변환 스크립트뿐이고 `geometry.py`와 `pipeline.py`는 수정하지 않았습니다.

- 검증된 벤치마크가 아닙니다. GSD는 추정값이고, GPS 절대 정확도, georef, 영상-GPS 시간 정렬은 미검증입니다.
- 한 시퀀스(03)의 균등 간격 260개이고 인접 프레임이 많아 독립 표본이 아닙니다.

같은 표본을 대상으로 성공·실패 변화량을 비교한 McNemar 검정 결과입니다.

| 데이터셋          | 표본 범위      | B128만 성공 / LoMa만 성공 | p-value  |
| ------------- | ---------- | ------------------- | -------- |
| Singapore     | k=0\~999   | 35 / 76             | 0.000125 |

| San Francisco | k=0\~999   | 1 / 6               | 0.125    |
| San Francisco | k=100\~999 | 1 / 5               | 0.2188   |

해석

- Singapore에서는 8방향 탐색으로 10m 성공률이 5.0%p 높아졌고, paired 비교에서도 통계적으로 유의한 차이가 확인됐습니다.
- San Francisco에서는 성공률 증가가 0.5%p에 그쳤고, 유의한 차이는 확인되지 않았습니다.
- 계산 시간은 약 0.22초에서 1.73초로 증가해 약 7.8배가 됐습니다.
- 따라서 8방향 탐색은 모든 환경에서 무조건 적용할 개선책이라기보다, 정확도와 계산 시간 사이의 선택지로 정리하는 것이 적절합니다.

주의: 위 표는 현재 공유된 팀 평가 기준의 결과입니다. 이전에 공유된 unclipped LSR10 결과와 섞어 쓰지 않아야 합니다.
